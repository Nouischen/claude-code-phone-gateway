Claude Code Phone Gateway 緣起做什麼安裝手機排錯GitHub
開源・Windows・純 PowerShell・零依賴

by 陳昱傑｜骨科醫師，順手把自己用的東西整理給大家

手機開的新對話，也能落在自己的電腦上

Claude Code 桌面版開的對話會自動出現在手機上；但反過來，手機主動開的新對話預設跑在雲端，碰不到你電腦裡的檔案、工具和設定。這個小工具補上反方向：讓你的 Windows 電腦一直掛在手機的裝置清單裡，手機開新對話就落在你自己的機器上，重開機、斷網之後也會自己回來。

三個指令裝起來 看程式碼（MIT）

來龍去脈：為什麼會有這個東西

我很常用手機交代 Claude Code 做事。以前在電腦上開一個新的 Claude Code 對話，還得先在對話框裡打一次 /remote-control，手機才看得到那一場；電腦重開機之後，更要先用遠端桌面連回去打指令。用久了就覺得，這件事 ChatGPT 的 Codex 做得比較像人：電腦配對一次，之後不管從電腦還是手機開新視窗，兩邊都同時看得到。

後來我才發現，Claude Code 其實早就補上了一半。桌面版的設定裡有一個開關叫 Connect new sessions to Remote Control（文件上的舊名是 Enable remote control by default），打開之後，電腦上每一場新對話都會自動連上手機，不用再打指令。我這台是 8 月下旬的桌面版更新之後就開始自動連的，只是我一直照舊習慣打指令，沒感覺到差別，9 月才真的注意到。

但另一半一直沒補上：從手機上的 Claude App 主動開一個新對話，預設不是開在我的電腦上，而是開在 Anthropic 的雲端伺服器上。AI 本來就在雲端跑，差別在於那個對話碰不到我電腦裡的檔案、工具和設定，等於是另一台空機器。我這幾個月累積的參考資料、記憶、各種自動化流程，它一個都用不到。

官方其實有解法，叫伺服器模式：在電腦上跑 claude remote-control，你的電腦就會出現在手機 App 的 Devices 清單裡，可以直接在上面開新對話。問題是它當常駐服務很勉強：斷網大約 10 分鐘會自己退出，開機也不會自己啟動。所以我先寫了一支常駐程式把它包起來，自己用了一陣子；這次整理成別人也能照著裝的版本，放上 GitHub。

手機 Claude AppCode 分頁 → Devices → 你的電腦 → New session
→
claude.ai 中繼只轉發訊息，程式碼與檔案不經過它
→
你的 Windows 電腦閘道讓 claude remote-control 一直活著；對話在這裡跑、用得到本機檔案

它做什麼，不做什麼

做的事

  • 把官方的 claude remote-control 伺服器隱藏在背景跑，沒有黑色視窗
  • 它退出就自動重開，連續失敗會退避，不會瘋狂重生
  • 開機自動啟動（只放一個「啟動」資料夾捷徑，不裝服務、不建排程）
  • 伺服器連續秒退三次就寫一個告警檔，不會默默壞掉
  • 附一支 doctor：逐項告訴你哪裡不符合、怎麼修，最後真的把伺服器起來測一次

不做的事

  • 不碰 Mac／Linux，第一版只支援 Windows 10／11
  • 不需要 Python、Node、管理員權限，也不改登錄檔、不動 feature flag
  • 不取代桌面版的自動連線，那個方向官方已經做了；它只補「手機開新對話落在本機」這一段
  • 不幫你登入。你需要 claude.ai 的訂閱帳號（Pro／Max／Team），API 金鑰走不通

順便講清楚：設定在哪裡、要開哪些

想要的效果在哪裡設定備註
電腦開的對話自動出現在手機Claude 桌面版 → Settings → Claude Code → Connect new sessions to Remote Control官方文件仍寫舊名 Enable remote control by default。我的實測是 8 月下旬更新後就預設會連，開關的狀態不一定對得上
終端機（CLI）開的對話自動連手機在 Claude Code 裡打 /config → Enable Remote Control for all sessions設定檔的鍵是 remoteControlAtStartup，放在使用者層級的 settings.json
手機主動開的新對話落在自己電腦上電腦上跑 claude remote-control（伺服器模式）這就是本工具負責讓它一直活著的那個程式
手機不用架東西也能交辦桌面版 Cowork 分頁的 Dispatch，手機配對一次走的是「傳任務給桌面版」，不是直接開 Code 對話；Pro／Max 限定
手機端選「電腦」不是選「GitHub 專案」。選了專案就是雲端對話，跟本機無關。

安裝：照著做就好，大約 3 分鐘

每一步都寫清楚：按什麼、貼什麼、會看到什麼。做完一步就打勾，勾勾會記在你的瀏覽器裡。

按鍵盤上的 Windows 鍵，直接打 powershell，按 Enter。會跳出一個藍色或黑色的文字視窗，最後一行長得像 PS C:\Users\你的名字>，後面有一個閃爍的游標。之後所有指令都是貼在這個視窗裡，然後按 Enter。

用一般方式開就好，不用「以系統管理員身分執行」。

按下面的「複製」，回到 PowerShell 視窗按一下滑鼠右鍵（在這個視窗裡右鍵就是貼上），再按 Enter。

git clone https://github.com/Nouischen/claude-code-phone-gateway.git

會看到類似這樣，最後一行是 done：

Cloning into 'claude-code-phone-gateway'...
remote: Enumerating objects: 30, done.
Receiving objects: 100% (30/30), done.

接著走進那個資料夾：

cd claude-code-phone-gateway

提示字元會變成 PS C:\Users\你的名字\claude-code-phone-gateway>，代表你站對地方了。

電腦上沒有 Git？用下載的方式

到 GitHub 頁面，按綠色的 Code 按鈕，選 Download ZIP。解壓縮到一個你找得到的地方，例如 C:\Projects。然後在 PowerShell 貼這一行進到那個資料夾：

cd C:\Projects\claude-code-phone-gateway-main

解壓縮出來的資料夾名稱結尾會多一個 -main，這是正常的。

貼上、按 Enter。它會一項一項檢查你的電腦，每一行開頭是綠色的 PASS、黃色的 WARN 或紅色的 FAIL。

powershell -NoProfile -ExecutionPolicy Bypass -File .\doctor.ps1

正常會看到這樣，版本號和路徑跟你的不一樣沒關係：

[PASS] Windows 10 build 26200
[PASS] PowerShell 5.1.26100.9168
[PASS] Claude Code 2.1.258
[PASS] claude.ai login found
[PASS] No ANTHROPIC_API_KEY in environment
[PASS] WorkDir C:\Users\you\claude-code-phone-gateway
[WARN] WorkDir is not yet trusted
[INFO] No startup shortcut yet
[INFO] Live probe skipped: WorkDir not trusted yet
Result: ready. 1 warning(s).

那一行黃色 WARN 是正常的，第 4 步會處理。只要沒有紅色 FAIL 就往下走。有 FAIL 的話，那一行底下就寫著怎麼修，修完再貼一次同一行重跑。

看到的紅字意思怎麼辦
Claude Code not found電腦上沒有 Claude Code到 官方安裝頁 裝好，再回來重跑第 3 步
No claude.ai login還沒用訂閱帳號登入過在 PowerShell 打 claude，出現畫面後打 /login，照指示登入，完成後打 /exit
Claude Code x.x.x is too old版本太舊打 claude update，跑完再重跑第 3 步
WorkDir is your user profile root你把程式放在家目錄本身把資料夾移到子資料夾，例如 C:\Projects，再 cd 進去

引號裡的「我的電腦」可以改成你想在手機上看到的名字。貼上、按 Enter。

powershell -NoProfile -ExecutionPolicy Bypass -File .\install.ps1 -Name "我的電腦"

大約 15 秒，會看到：

[1/4] work folder marked trusted in ~/.claude.json (backup: ...)
[2/4] live probe: starting claude remote-control once...
2026-09-06 03:50:39 connected: https://claude.ai/code?environment=env_...
OK  remote-control server connected.
[3/4] startup entry created: ...\Startup\Claude Code Phone Gateway.lnk
[4/4] gateway running and connected: https://claude.ai/code?environment=env_...

Done. On your phone: Claude app > Code > pick this computer under Devices > ...

看到 [4/4] gateway running and connected 就成功了。之後電腦開機它會自己啟動，你不用再碰它，PowerShell 視窗可以關掉。

如果最後一行是 Install stopped: the server could not connect，往上看紅字寫什麼，通常是第 3 步那張表裡的其中一種，修完重跑第 4 步。
  1. 打開 Claude App，點下方的 Code
  2. 找到 Devices（裝置），點你剛才取的名字。旁邊有綠點代表在線
  3. Directory（資料夾）選 claude-code-phone-gateway，按 New session
  4. 對它說一句：列出這個資料夾裡的檔案

它回你 doctor.ps1、gateway.ps1、README.md 這些檔名，就代表這場對話真的跑在你的電腦上。以後在這裡開的每一場對話，都用得到電腦裡的檔案。

如果 App 要你「選一個 GitHub 專案」，那是雲端對話那條路，退回去改從 Devices 裡點你的電腦。

更省事：叫你自己的 Claude Code 幫你裝

如果你電腦上已經有 Claude Code，第 2 到第 4 步可以整包交給它。打開 Claude Code，貼這句：

請照 https://github.com/Nouischen/claude-code-phone-gateway 的 README 把它裝起來，安裝名稱用「我的電腦」，每一步把輸出給我看，遇到 FAIL 就停下來告訴我

repo 裡有一份 CLAUDE.md 是專門寫給它看的，它會知道該怎麼做、什麼不能做。

之後想移除

回到那個資料夾，貼這一行。它會停掉程式、拿掉開機捷徑，紀錄檔留著。

powershell -NoProfile -ExecutionPolicy Bypass -File .\install.ps1 -Uninstall

最後一行應該是 Uninstalled (1 process(es) stopped, none remaining)。

進階：紀錄檔在哪、怎麼看它活著

所有紀錄都在 <工作資料夾>\logs\：

檔案看什麼
gateway.log管家事件：server started、connected: <網址>、server exited、restarting in Ns。健康狀態＝每次啟動後都有一行 connected
server.log伺服器自己的輸出，超過 2 MB 自動輪替。出事時真正的原因在這裡
ALERT-gateway.txt連續三次秒退才會出現，恢復時再寫一行

斷網之後伺服器每隔幾分鐘重啟一次是正常的，它自己退出、管家把它帶回來。要移除就跑 install.ps1 -Uninstall，會停掉程序、拿掉捷徑，紀錄和信任設定留著。

會靜默失敗的地方

這幾個都是我自己踩過、而且壞掉時沒有任何聲音的。工具現在會處理，但知道原因比較不會慌。

症狀原因處理
FAILWorkspace not trusted工作資料夾沒被信任install 會種信任旗標；手動做法是在資料夾裡跑一次 claude 並按同意
FAILrequires claude.ai subscription auth環境變數裡有 ANTHROPIC_API_KEY，claude 改走金鑰認證管家啟動伺服器時會把 ANTHROPIC_* 剝掉，你的全域變數不用刪
WARN每 30 秒到 10 分鐘就 rc=1 重啟上面任一種認證或信任問題看 server.log，告警檔會寫最後一行
FAILhome-directory trust is never saved工作資料夾設成了家目錄換一個子資料夾，這是官方的安全設計
正常斷網約 10 分鐘後伺服器退出官方設計管家會用 30 秒起跳、最長 10 分鐘的退避重啟
正常手機清單多了幾個閒置項目伺服器每次啟動會預建一場滑掉就好

做的過程：怎麼確定「別人真的裝得起來」

我沒有第二台 Windows 可以測，所以用另一種方式：開一個全新的 Claude Code，扮演完全沒看過這個專案的陌生人，只准讀 README，從 clone、doctor、install、驗證、移除全程自己做，中途我不插手。這樣跑了三輪，前兩輪各抓到一個真的 bug：

  • 移除指令沒把常駐程序關掉，因為過濾程序的字串比對把 session 名稱裡的「-test」誤判成測試模式
  • 安裝後再跑 doctor 會多開一個探針、移除時的計數印成空白，根因是 PowerShell 把只有一個元素的陣列拆掉了
  • 自己再測時又抓到一個：taskkill 的錯誤訊息在嚴格模式下會把整支移除腳本中途殺掉，改成不靠 taskkill 的程序樹終止

第三輪全部通過。另外補測了幾條 README 宣稱但陌生人沒踩到的失敗路徑：工作資料夾設成家目錄、claude 路徑錯、環境變數帶 API 金鑰、用桌面版內建的 claude.exe，反應都跟文件寫的一樣。

誠實的邊界：全部在我這一台、npm 安裝的 Claude Code 上測的；原生安裝器的路徑有寫偵測但沒實機驗過；Mac 明寫不支援。Anthropic 正在往原生化走，哪天官方內建了常駐伺服器，這個工具就可以退役，那是好事。
